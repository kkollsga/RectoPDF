# Dependencies: notices

> Part of the engineering notes: [`README.md`](README.md).

**Notices.** `THIRD-PARTY-NOTICES.txt` lists every third-party component that ships and its licence text, and `app/build.sh` copies it into the bundle as `Contents/Resources/Licenses.txt`. `tools/notices.py` writes it, offline, from `cargo metadata` of both workspaces: the normal dependencies, on `aarch64-apple-darwin`, of the six binaries in the bundle ship, and every other package in either lockfile is listed as not shipped with why, so the file accounts for each one. PDFium's own third-party licences (FreeType under the FTL, libjpeg-turbo, OpenJPEG, ICU, lcms, libpng, zlib, abseil, AGG and the rest) come from its release tarball, which `tools/pdfium.sh` checks by digest and now unpacks into `target/pdfium/licenses`. A text many crates share word for word is given once. Against MIT: everything is MIT, Apache-2.0, BSD, Zlib, Unicode or Unlicense, except the uniffi crates, MPL-2.0, used unmodified with their source published; the MPL text, which they don't carry, is in `tools/notices/`. `recto-cli`'s `notices` test fails when a lockfile and the inventory disagree, PDFium's pin moves, a shipped licence offers nothing an MIT app can ship, or the bundle's copy differs. Run `tools/notices.py` after any dependency change. The Swift app has no package dependencies.
