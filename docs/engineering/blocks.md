# Blocks: the helper's `blocks` job and the session's `BlocksAnswer`

> Part of the engineering notes: [`README.md`](README.md). The design is `docs/design/blocks.md`; this is what S3 built (2026-11-27, `build/blocks-s3`). **No UI.** The store that writes to the corpus folder and the queue that runs the job are S4's (the last two sections, 2026-11-28, `build/blocks-s4`).

**The route.** The structure helper (`recto-headings`, only ever as the walled `RectoStructure.app`, [`generated-contents.md`](generated-contents.md)) takes a third job beside `count` and `headings`: `{"kind":"blocks","memory_limit":…,"scan":"typography"}` (`structure::blocks::job()`). It opens the document on descriptor 3 as `LazyStrict` with images off, scans (typography unless the job says `"scan":"full"`), and says one line a page. The session reads each line with `recto_index::blocks::map::PageLines::read`, maps it with `map_line` against that page's text from a `PageStore`, and hands the store each page's `PageBlocks`, once, in page order (`structure::blocks::BlocksAnswer`). The helper never sees the page's characters, and the session never sees distillPDF's markup.

**What the helper says** (`recto_headings::blocks`, pure parts tested without a process):

- A page line: `{"page":N,"blocks":[{"kind","level","box":[l,b,r,t]|null,"text","continues"}]}`, `page` zero-based, for every page of the document, including those with no blocks (`"blocks":[]`) and those distillPDF couldn't make.
- `kind` is `para`, `heading`, `list_item`, `caption`, `code`, `footnote`, `table` or `figure`. The page-chrome carriers (`header`, `dest_anchors`) are never sent. `level` is a heading's, at most 9, and 0 for any other kind. `box` is null unless all four sides are finite. `text` has distillPDF's inline markup taken out as a heading's title does (`plain`), and is `""` for a table or a figure: never their cells or markup. `continues` is true when a continuation of that block starts on a later page.
- A block whose own JSON is over half the line cap (256 KiB) is left out, and the later ones still go. Otherwise blocks go in order while the line, with its closing `]}`, stays within 512 KiB (`recto_index::blocks::map::MAX_LINE_BYTES`) and 4,096 blocks; the first that doesn't fit and the rest of the page are cut. Every cut block is counted.
- A page distillPDF can't make is a line with no blocks and a count in the end line: **a page never ends the job** (a document whose page 5 fails still has pages 1 to 4 and 6 onward). Stale statistics or a cancelled walk, a file changed under the read, is `{"state":"changed"}`.
- The end line is `{"state":"ready","pages","pages_failed","blocks","cut","distilled_ms","helper_peak_bytes"}`, numbers only. `blocks` is how many went out in page lines.
- It holds one page's output at a time. A write that fails (the session killed it) ends it quietly.

**What the session believes** (`structure/blocks.rs`; the runner's rules are [`generated-contents.md`](generated-contents.md)'s):

- A page line is every page once, in order: a gap, a repeat or a page out of order is `bad_answer`; a page at or past the index's page count is `pages_differ`. A line that isn't a page line is parsed as an object and is the end line, or a `refused`/`changed`/`failed` that is believed **only as the first line** (`structure::instead`, shared with `headings`: a refusal's code is one of three known ones, and a failure's own words are never repeated).
- The end line must say `pages` equal to the lines taken **and** the index's own count (else `pages_differ`), `pages_failed` no more than that, `blocks` equal to the sum over lines of readable candidates plus unreadable blocks, a number for `cut`, at most 32 entries all numbers or bools but `state`, and none of the session's own names (`walled`, `elapsed_ms`, `helper_peak_watched_bytes`).
- A [`PageStore`] gives a page's characters as the index keeps them (`recto text`'s numbering; false means no text: the page maps nothing and is counted in `pages_without_text`) and takes the mapped blocks. It may stop the job with a code of its own (`put` is `Err(code)`), and **that code reaches the caller as it is**: the runner reports `answer.stopped_for()`, then a limit's code, then `bad_answer`, so a store's `too_large` isn't read as a hostile helper. The helper is killed at once.
- **The runner's caps are the answer's own** (`Answer::max_line_bytes`, `max_answer_bytes`, defaults the headings job's 64 KiB and 4 MiB): a blocks line is at most 512 KiB, and the answer at most 4 MiB plus 64 KiB a page, up to 2 GiB. The reader thread's 256 KiB stack holds a 512 KiB line of `[` (serde_json refuses past 128 deep).
- `numbers()` (measuring only): the helper's end-line numbers, then `pages`, `pages_without_text`, `candidates`, `stored`, `dropped` (unreadable included, so `stored + dropped = candidates + unreadable`), `stored_<kind>` and `dropped_<kind>` for the eight kinds, each reason of `Drops`, `unreadable`, `map_ms` (reading the page's text, mapping, storing) and `answer_bytes`. `into_parts()` gives the store and a `BlocksTally` for S4 to keep.

**Held by tests.** Helper (`crates/recto-headings/tests/blocks.rs`, with `helper.rs` and `sandbox.rs`): every kind reads back as the session reads it; the line cap at the limit and one byte more; the real helper on `recto_testpdf::blocks::blocks_document`, form bomb, all 15 hidden headings and the hidden-text page; the walled and bare helpers say the same lines; a job that names a file is refused; typography is the default. Session (`structure/blocks/tests.rs`): the nine in-process cases, one with a stand-in helper. Integration (`recto-control/tests/structure.rs`): the real walled helper on the blocks document, and `blocks_measure`, a measurement. Fuzz (`distill_line`): the same hostile lines, wrapped as a helper says them, through `blocks::read_all` with a store in memory.

## S4: the store and the queue (2026-11-28, `build/blocks-s4`, no UI)

**Made only when an agent asks:** the first `get --grain paragraph|section|chapter` or `recto wait blocks-ready`. Never on opening a tab, never by the window. A `get` that starts it answers the page at once with `widened.why = "blocks_building"`; reading the stored blocks back is S5's, so until then a `get` after they're made says `blocks_not_made` (the coordinator's answer, 2026-11-28: no third word).

**The store** (`recto_index::corpus::blocks`, in the corpus folder of that `CorpusKey`): `app/blocks.bin` is each page's `codec::seal_page` record end to end; `app/blocks.sealed` is `Purpose::BlocksHeader` over `[rules tag 16] [pages] [pages without text] [unreadable] [stored 8 x u32] [dropped 8 x u32] [bin bytes u64]` and then, for each page, `[offset u32] [length u16]` (128 bytes and 6 a page). The rules tag is the first 16 bytes of SHA-256 of `BLOCKS_RULES` (`"distillpdf fbf5b22 typography"`), the record format and `"recto-blocks/1"`; `recto-headings/tests/lockfile.rs` holds that the pinned distillPDF revision starts with the one named. A header of another tag isn't damage: nothing is used, nothing is thrown away, the next build replaces it.

- **All or nothing.** `BlocksBuild::begin` takes `build.lock` (a `clear` and an `evict` skip the folder while it's held, as for an index build), opens the finished corpus, returns `Made` if a header of these rules and this page count is there, and otherwise removes the header first, then the bin. A page's record is appended as it's put, the header is written last, after the bin is synced, and then the corpora are evicted to their limits. A build dropped before `finish` removes its bin; a real kill leaves a bin with no header, which reads as not made.
- **The limit.** Text plus blocks count against `BuildLimits::max_doc_bytes`: `corpus_bytes + bin so far + (header at its final size)`, checked at each page, so the last page can't be the one that finds it's over. `TooLarge` at the limit plus one leaves nothing.
- **Reading.** `StoredBlocks::open` reads at most 128 bytes + 6 a page, and refuses (`Damaged`) a table that isn't contiguous from 0, a length outside a record's bounds, a bin whose length isn't the header's, a table or figure stored, or counts that can't be. A header for 200,000 pages is 1.2 MB. A damaged set is removed by the caller and counts as not made. `page(p, chars_now)` reads one record by offset and opens it as page `p`'s (`OpenError::{Damaged, Stale, Foreign}`).
- **Hidden text.** A block made of hidden characters is stored like any other: a block is only where characters are, and `get` marks hidden text from `recto text`'s own spans, never from the blocks.
- **A new version, `index clear`, the sweep and the size and age limits** need no code of their own, as the files are in the key's folder (`a_new_version_of_the_file_takes_the_old_versions_blocks`, `a_clear_or_sweep_skips_a_folder_being_built_and_takes_it_after`).

**The queue** (`recto-control`): blocks share the generator's one queue and its one helper with generated contents (`What::{Contents, Blocks}`, `Job`): newest ask first across both kinds, `MAX_WAITING` counting both, one helper at a time, utility priority, 512 MiB, `time_limit(pages)`. Remembered per `(What, CorpusKey)`: a refusal, or a limit (`over_memory`, `out_of_time`, `too_large`, `pages_differ`), is that version's own and never run again; any other failure pauses 60 s. A cancel of one kind touches only that kind; a closed tab stops both. `Walled::run` begins the build (`NotIndexed` is `index_not_ready`, `Busy` is `busy`, `Damaged` is `index_damaged`, `Made` is `AlreadyMade` and starts no helper), runs the helper, and `outcome_of` writes the header **only for an answer believed to its end, of the file asked for (looked at by path as well as by descriptor), not stopped since**; every other end drops the build. A job killed for `cancelled` or `out_of_time` can still have put pages from what its pipe held: they're staged in the bin and thrown away with the build. Events: `blocks_building` and `blocks_built` (group `blocks`), numbers only and all the session's own.

**The surface** (`recto-agent`): `Blocking` (`want`, `state`, `cancel_files`, `making`), `blocks::why_page` (one key, one ready-file read, one header open, nothing that waits), `wait blocks-ready` (numbers only: `stored`, `dropped`, `bytes`, `bytes_per_page`, `by_kind`; `blocks_refused` and `blocks_failed` with Rust's words), and `index clear` stopping a blocks build before it clears.

**Measured (S4),** 2026-11-28, release `recto`, `recto-indexer`, render service and structure helper, one run each, `blocks_measure` (`cargo test --release -p recto-cli --test index blocks_measure -- --ignored`, `RECTO_BLOCKS_FILES`, a copy of each file in temp state), the Mac with other agents building (load 9 to 10 on 10 cores, so the times are for a busy machine; the helper at utility priority). The serving process's own peak footprint was not measured (its pid isn't in reach of the test). `elapsed_ms`, `map_ms` and the helper's peak are the session's own numbers from the `blocks_built` event.

Bytes a page is 205 to 355 against S0's estimate of 76 to 259: GDPR and the UN report are over its top because their pages hold many short blocks (18 bytes a block, plus the 28 and the 6 of the seal and the table), a block count S0 didn't have for them. A page with the most blocks (512) is 9 KiB, so a hostile file's blocks are stopped by the document's size limit (`too_large`, tested at the limit and one over), not by the format. **What one hostile page line costs the session** (`recto-control/tests/blocks_cost.rs`, a counting allocator, a debug build, a 512 KiB page line of `[],` or of short objects against a page of 2,000,000 characters, the most a corpus holds): 12.5 and 13.4 MiB over the session's own, against the S3 review's estimate of 6 to 10 MiB. The page's characters are 8 MB of a `Vec<char>`, and the parsing of the line is the peak that sets the number. The buffer of a page past a megabyte of room is given back at the next page.

**A build holds the index's lock, and what an agent sees of that** (the coordinator's decision, 2026-11-28). While blocks are being made the corpus's `build.lock` is held, as an index build holds it. So for as long as a job runs (at most `time_limit(pages)`: three minutes and a second a page, up to half an hour; a minute for a small document) an agent's `recto index --agent` on that document answers `busy` ("Try again in a moment."), a retry of failed pages waits, and `clear` and the sweep skip the folder. `recto index clear` stops the build first and waits for it. A stopped or failed job leaves no bin, so nothing stays held. Accepted: nothing else of the index is read through that lock (Find and search read `ready.sealed` and the pack, which a blocks build never writes).

**Who asks, and what is remembered.** The queue's asks are a person's or an agent's (`want_as_person`: the window's note and a person's own `contents show`; everything an agent sends, by whatever route, is an agent's). A person's waiting ask is never given way for an agent's and goes before them; past 8 the agents' oldest gives way. What is remembered of a version (a refusal or limit forever, a failure for a minute) is kept 32 for each kind, so a flood of one kind's refusals can't make the queue forget the other's. Nothing is announced for blocks that were found already made.

## S5: reading blocks back (`get --grain paragraph|section|chapter`)

- **The pure builder** is `recto_index::blocks::unit` (`build(pages, ask)`): one page at a time through the `Pages` trait, so every rule above is tested with no file, helper or app (`blocks/unit/tests.rs`). The glue is `recto-agent/src/getting/blocks.rs`: it opens the corpus, the stored blocks, the contents and the file once, implements `Pages` (index first; a live read when the index didn't check the page for hidden text, for at most 5 s), and turns the builder's marks into tokens with the page's own `Referrer`. `recto-agent/src/blocks.rs::readable` says what can be read or why the page is answered.
- **Caps:** 64 pages read for an answer, neighbours included, and exactly one page more, read only to name where the answer goes on (`more`'s reference needs its characters' check), so 65 reads at most; its text is never given. Live reads stop at 5 s.
- **Memory:** `recto-index/tests/blocks_unit_cost.rs` (a counting allocator): one answer holds one page's characters and what it gives, however many pages it reads.
- **Format:** the header gained the corpus's `retries` (`recto-blocks/2`); older headers read as other rules and are made again on the next ask.
- **Known limit:** on a page with columns, a `more` reference in a gap after a block whose place is above the section's start can anchor in the section before. Reading order across columns is not character order, and a section's edges are cut by place.

**Measured (2026-11-28, debug build, load 7 to 14 on a 10-core Mac, one run, so estimates; each figure is a `recto get` round trip through the CLI, so it includes starting `recto`):** NASA `gov_nasa_ntrs20240002628`, blocks made, 20 calls each. A paragraph on page 20: p50 91.1 ms, p95 97.0 ms (2 pages read: its own and the next block's). A section of 29 pages by generated contents: p50 94.0 ms, p95 95.8 ms, cut at 15,997 characters after 10 pages read; 84% of the characters given were outside any stored block (13,461 of 15,997), given as plain paragraphs. Not measured in a release build (the structure helper isn't built there by `cargo build --release` of the workspace). One page's characters held: the memory test's section peak is 8,263,536 bytes against a page of 8,000,000, the paragraph 8,000,882 over 64 pages read; its bound is 12,000,000.

**Going on through nested sections (`refs.more_entry`, `--entry`).** A section's `more` can't say which entry it was of (the locator has no room), so the answer carries `refs.more_entry` and the caller passes it back as `--entry N` with `--from-here`. It is used only if it is an entry of the contents read now whose range reaches the reference's page; otherwise the anchor rule decides (the last entry whose cut is at or before the character). The contents' identity is not checked (no state is kept), so a number from other contents that happens to fit gives the wrong section on that page: bounded to that page's own text, no leak.

## S5c1: a paragraph over pages, `get`'s end check, headings above a hit or a page (2026-11-28)

- **A paragraph joined across pages** (`unit::Walk::join_on`). A stored block with `continues` set (a paragraph, list item, caption or footnote) is given with its continuation: the first block of the next page that has blocks, if it is the same kind; pages the tab doesn't show and pages with no text are passed over (at most 8 with no text, none read), and a page with text but no blocks is read and passed. The answer is one paragraph (text: pieces joined by the page's `\n`; Markdown: `unit::as_markdown` merges a piece that `joins` the one before into one block, so it isn't two paragraphs). `unit.pages` is the pages spanned, `unit.chars` the characters of the pieces reached, `refs.next` the block after the last piece reached, `unit.continues` the last piece's bit (so false once joined to the end, and true only where the walk was cut). **Bounds:** the same as any answer: 64 pages read and one to name where it goes on, `--max-chars` (a later piece is not given in part: the cut is before it and `more` is its start), the 5 s of live reads. A store that sets `continues` on every page is followed for 64 pages and no further (`a_store_that_forges_continues_on_every_page_is_followed_only_to_the_page_cap`); the chain stops where a page's first block is another kind.
- **`slow::Seam::Get`** (`get`, between its read and its end check of the file's version and index key; 50 ms in `ci`). `getting/tests.rs` holds it with the gate, replaces the file, and sees `file_changed`. The index-key re-check after it can't differ from the stamp's in a test (a replaced file has another stamp), so the stamp check is what the test seeds.
- **`headings_above` for `hit` and `page`** (`getting/blocks.rs::headings_of_page`). The contents are the section grain's (`contents_for`): the file's own if `judge` says fine, else generated ones if made; `get` never starts them. **The outline the tab holds is used** (`Session::warm().toc`, for a tab with no edit list, whose page count is the file's), and the file is read (`DocLoader::load`) only when nothing is held: before this, the section grain read it on every call, and so would a hit. `headings_at` says where they were read: `block` for a hit whose page has stored blocks, one of which holds its first character (that block's place, `Place::of_block`, as a paragraph's; stored blocks are used where they are and **never asked for** by a hit), else `page_end` (a page, or a hit with no such block): the headings in force at the foot of the page, so a section starting on the page is named and one that ended on it isn't. `[]` with no usable contents.
