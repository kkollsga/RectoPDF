# The QA channel

> Part of the engineering notes: [`README.md`](README.md).

**Who quits.** `recto stop` is refused by a normal app, and says only the user quits it. A quiet run stops when told.

**The QA channel.** `recto qa start` runs the app with `--qa` on a state folder set with `RECTO_STATE_DIR`, and the app refuses anything else. Its session opens and writes files only in the system's temp folders, at Full or any level, for the person's routes and an agent's alike (`agent-interface.md`, threat T16), so a test or script copies what it opens into its temp folder (`cp -c`, a clone) and writes its shots there: `app/qa/quiet-files.sh` does that for the shot scripts. It has the activation policy `.prohibited` from before AppKit does anything, so no Dock icon or menu bar and it never activates. Its window is never ordered in, sits off every screen, and draws as key at 2x. No sheet or panel is ever begun on it: AppKit orders a window in to hang a sheet on it and slides one that's off screen onto the nearest screen first, which flashed a quiet run's window up in the lower left each time the print panel or a close prompt came and went (owner, 2026-11-08). Every sheet and panel goes through `SheetPresenter` (`app/Sources/RectoPDF/Sheets.swift`), which in a quiet run makes it and holds it, never shown; `qa sheet-answer` runs the completion a click would, and `qa shot` draws an alert from its own window where it would hang. The print panel, Save As and Open have no window of ours to draw, and About isn't shown. `a_quiet_run_never_puts_a_window_on_screen` samples the window server's list (`recto_platform::screen`) every 2 ms through a run's start, sheets, Settings, a print and shots, and fails on any window of the app's on it. And a quiet run answers the system's reopen, open-documents, print and get-URL events itself, by doing nothing, from before AppKit finishes launching (`QuietRunGuard`, `app/Sources/RectoPDF/QuietRun.swift`): LaunchServices hands an `open` of the same bundle, from anyone, to the running app, and AppKit's own handling turned a quiet run into a regular app with a Dock icon and menu bar, which a full check's restore test saw while another worktree's update tests were opening their copies. Its policy is watched and put back should anything else change it (`a_quiet_run_stays_quiet_when_the_system_opens_it_again`). There's a 10-minute limit, and a run ends sooner with what started it (`qa::end_with_starter`): its owner process (`--qa-owner-pid`, from `recto qa start --owner` or `RECTO_QA_OWNER_PID`, which `State::command`, the QA scripts, the corpus run and the soak set to their own; an update's relaunch passes it on), its state folder going, or its own program being deleted, as a worktree's removal or a rebuild does. One thread asleep in one `kevent` (`local::wait_until_gone`), with no wake-ups. `recto qa state` reports what the app says it's showing. `recto qa shot` draws the window's frame view with `cacheDisplay` into a 2x bitmap, which needs no permission. Before a report and each look `recto qa wait-settled` takes, the QA channel lays out the run's windows, as a display cycle would for a window on a screen, which a quiet run's never is (CI, 2026-11-11: a table with no rows made after a restart). `recto qa wait-settled` goes through the session thread's queue first, then waits for what's visible to be on layers, then asks the host until no animation that changes what a shot shows is running (`app.animations` in `qa state`: the sidebar contents' fade and slide, their drift, a name about to show, a ⌘-scroll zoom about to go sharp), all within the one timeout. Drive verbs call what the event calls, and answer after that's been through the session thread and laid out, so no script sleeps. `recto qa run` runs a script and gives PASS or FAIL, and a 2 s stall fails it. `recto qa sweep` reports each contents move, with its length and peak, and the rests between. `qa` rows are Read-only or Control, and a session that isn't a quiet app answers `qa_needs_app`. They're in `recto help`, and left out of the skill. **Not covered:** the step from a real event to the method it calls has no unit test, only the method. Run-loop blocks from Rust are in their own autorelease pool, as AppKit only drains its pool after an event.

**The watchdog.** The UI thread says when it wakes and sleeps, from a run-loop observer. One thread watches only while it's awake, looking every 250 ms, and notes 1 s and counts 2 s. `recto qa stall` proves it fires.
