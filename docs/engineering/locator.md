# References: `recto ref` and `recto resolve`

> Part of the engineering notes: [`README.md`](README.md). The core is `crates/recto-core/src/locator.rs` (design: `docs/design/locator-core.md`).

A reference is a short token that names a page by its content as well as its number, so a page can be found again after another program added, removed or moved pages. `recto ref <page>` makes one, and `recto resolve <ref>` says where that page is now. Both are read-only (`Level::ReadOnly`), run on one executor (`crates/recto-agent/src/locating.rs`), and are registered by `crates/recto-agent/src/commands/locating.rs`. The window has no control for them: there is no person's path to a reference yet.

**What the answer is.** `resolve` answers with a status and exits 0, except for a character target on a found page whose text can't be read (below): `found` where the reference said, `moved` when the file's only page with that content is somewhere else, `ambiguous` when several have it (the candidates are listed, never the nearest), `gone` when every page was read and none has it, `incomplete` when a cap or an unreadable page stopped the search, which never says gone, and `text_changed` when a reference to characters finds its page but the text at those characters isn't what it was made of. Document tags are information beside the status (`document`: `same`, `different`, `unknown`) and never decide it. A hinted page with the reference's own digest is `found` without reading the rest, whatever the file's version: identical page content is the same page.

**Refusals** are for what can't be answered at all: `bad_reference` (exit 2) for a token that isn't one, refused when the line is read, before the level or the tab is asked, in constant words that never repeat it; `reference_too_new` (exit 2) for a version this build doesn't know; `not_referenceable` (exit 1) for a renderer-only file, a page with no identity, a document with no tag, or a page added from another PDF and not yet saved; and the existing `no_such_page`, `no_such_tab`, `file_unreadable`, `file_changed` (the file changed while it was read), `source_changed` (the tab's edits are about another version of the file, or its pages are withheld: as `text` and `contents` refuse) and the protected-document refusal.

**Unsaved edits.** A reference names a page of the tab's own file. `ref N` counts pages as the tab shows them and finds the file page standing there; `resolve` answers `file_page` (of the file on disk) and `page` (its place in the tab now), which is null when unsaved edits removed it. A spot's rectangle is in the file's shown frame, before any unsaved turn, and the answer's `note` says so.

**Cost and safety.** Nothing is kept: no state, cache, thread, event or per-tab field. The session lock is held only inside `tab_file`; the file is then opened by its own descriptor (`recto_session::identify::Opened`), read under `ScanCaps::STANDARD` (1 GiB of page reads, at most 200,000 pages), and its stamp is checked again after. The token is never logged: `log_details` holds the tab and the page number the token hints at.

## Character references (`recto ref <page> --chars S-E`)

`recto ref 3 --chars 120-180` makes a reference to characters `[120, 180)` of page 3's text (characters are Unicode scalar values, the end not included, counted in `untrusted.text` of `recto text`). The token is r1's `.c<start>-<end>-<check>` form, with the check frozen as `recto-text/1`: the first 8 bytes of SHA-256 of `"recto-text/1\0"` and the UTF-8 of those characters (`crates/recto-core/src/locator/text.rs`). The core hashes the text it is given and never normalises; the executor always reads text through `recto_index::read_page`, the reading `text` and `search` share. Any change to the check is `recto-text/2` and token `r2`. `--chars` that is empty or ends past 2097152 is `usage` before the file is opened; one that ends past the page's text is `not_referenceable`. The answer adds `chars: [S, E]`. A token with an arbitrary check is no different from one whose page changed.

`resolve` (and `--ref` on `text` and `render`, through `page_of`) go through one function, `locating::resolved`. For a character target on a page that is `found` or `moved`, it reads that page's text with the session free, checks the same offsets only (nothing is searched for elsewhere on the page), and checks the file's stamp after the read as well. The answer's `target` is `{ kind: "characters", start, end, checked: true, text: "same" | "changed" }`. A character target on a page that is found whose text can't be read at all (the renderer fails or is stopped on it) is not a status: it is the refusal of the read of that page's text (`render::page_text`, the one reading `recto text` makes of the characters, with its code and exit), since a page nobody can read hasn't had its text changed. It is `recto text`'s refusal for a page the characters can't be read of; `text` also runs the hidden-text check, so it can refuse `renderer_misbehaved` when that check's job is rejected, and `page_text` skips the check and doesn't. When the text is changed the status is `text_changed` (exit 0) with `page` and `file_page`, and `text --ref` and `render --ref` refuse it as `reference_unresolved` in words of their own; only `found` and `moved` with the same text give a page. A protected document, a level below Read-only and every other refusal are the commands' own.

## References on search hits

Each phrase, regex and ranked hit of `search` carries `chars` (`[start, end]`, Unicode scalars of `recto text`'s text of the page, end excluded, trailing whitespace trimmed) and `ref` (an r1 token with the `recto-text/1` check, as `recto ref --chars` makes one), or both null. The answer carries `references: { made, missing, note }`. A ranked hit's `chars` and `ref` are of the word its line shows (`first_term` of the page's text, the same range its snippet is cut around), so `ref` points where the snippet points; an `also_spelled` ranked hit gets a reference to its page and null `chars`. A ranked search makes one reference per hit, at most `MAX_LIMIT` (200), inside `HIT_REF_CAPS`; its deadline is the second pass's (`settings.second_pass_until`), since that pass runs past the first pass's by design. They are made in `crates/recto-agent/src/locating/hits.rs` (`HitRefs`), which `search.rs` calls once per hit (`mark`) and once at the end (`finish`); the core's `Referrer` (`reference()` is its one-page wrapper) reads the page identities.

- **Cost per search, bounded:** the tags once (at most 16 page reads), a page once for all its hits, under `HIT_REF_CAPS` (256 MiB, 16 + 200 pages). Characters are counted on from where the last hit ended, so a page costs its length, not its hits times its length (`walked` in the test). A search with no hits opens nothing. Nothing is kept after the call.
- **Where the page reads come from (2026-11-26).** A hit read from the index (its page view carries the corpus key) is referred to from the identities the indexer stored beside the text (`recto_index::corpus::Identities`, `ids.bin` and `ids.sealed`): `Referrer::over` runs the same caps, memo, tag rule and `Unreferenceable` mapping over a `PageSource`, so the token is the one the file's own reads make, and **no file is opened** (`a_search_from_identities_opens_no_file_and_makes_the_files_own_tokens`). The file is read live as before for `--scan`, a file opened with a password, an added file's pages (which get no reference anyway), an index with none stored (built before 2026-11-26, or without lopdf's page map, or past `BuildLimits::identity_bytes` or the page cap) or stored under other rules (`stored_rules_tag`: the digest name, every field of `Caps::STANDARD`, the decoders' limits, `TAG_PAGES`, the tag's name), and when the search's caps are not `Caps::STANDARD`. At most 200 records are read per search besides the tag pages (≤ 16), under `HIT_REF_CAPS`. **Never stale:** `finish` checks the file's `CorpusKey` (which has the change time) as well as its stamp whenever stored identities were used, because the stamp (size, time, device, inode) is the same after a file is rewritten in place with its size and time put back (probed 2026-11-26 in `a_file_rewritten_in_place_with_its_size_and_time_restored_withdraws_every_stored_ref`); every `ref` is then withdrawn as `file_changed`. **A record that doesn't open as its page's** (a flipped byte, another page's record in its slot) or an `ids.bin` a record short or long: the identity files are removed, that hit and the rest of the search's hits are counted `file_unreadable`, and the next search reads the file. Digests and tags are in the sealed files only, never in the answer, the log or `index` status.

- **`missing` codes:** `added_file`, `not_on_characters`, `empty`, `past_character_cap`, `no_such_page`, `no_identity`, `no_document_tag`, `caps`, `file_unreadable`, `file_changed`. Order of checks: added page, range, file, page.
- **File changed during the search:** the stamp taken at the start is checked again at the end; on a change every `ref` and `chars` is withdrawn and `missing` is `{ file_changed: <hits> }`.
- **Another spelling** (`also_spelled`, phrase or ranked) gets a reference to its page and null `chars`.

## Known limits

- **Index offsets against renderer drift.** A hit answered from the index carries the corpus text's offsets; if the renderer changed since the corpus was built, its reference resolves `text_changed`, honestly.
- **Characters are never searched for elsewhere on the page.** A reference to characters is checked at its own offsets only; if the words moved within the page it says `text_changed`.
- **Added copies (not fixed in slice 3):** `resolve`'s `page` counts only the tab's own slots, so a reference from a copy added from the tab's own file would resolve to the original's place or `removed`, never the copy's; fix both together.
- **An index built before 2026-11-26 has no stored identities,** so its references still open the file (the earlier timing rows) until the file changes, `index clear` runs or the index ages out (90 days); nothing backfills it. An index made under other digest caps or limits is treated the same, and is not damage.
- **A flate2 upgrade can move pages that sit at the decode-work limit** between "has an identity" and "has none", for stored identities as for live reads; the rules tag does not cover a dependency's version, and an index built before the upgrade keeps what it stored until it is rebuilt.
- **Trust.** The helper writes the identities, so one that is replaced can forge references as it can forge the corpus's text; `resolve` and `--ref` always read the file live, and a reference to characters checks the text. A forged reference to a page alone could still send `text --ref` to another page: the same trust as the security read of 2026-11-15.
- **A ranked reference is the first shown word, not the best passage.** It points at the word the hit's line shows, however the page scored.
- **`render --ref` reads the text once more before drawing** (its reference's characters are checked first), where `text --ref` reads it once.
- **2026-11-25 (`build/page-id-caps`):** the names cap went from 256 to 8,192, so the 383-page NASA report now answers `gone` for a page that is really gone (the numbers are in the table above). Before, four pages (zero-based 127, 137, 156, 197) had no identity because they draw more than 256 images. Eleven pages of bench100 gained an identity, and no digest that existed changed. At 256 MiB the scan had stopped 24 pages short, because a stream a page draws is charged each time it is drawn.
- The 330 MiB USGS map has one page, and that page still has no identity (it reaches `page_bytes`, correct under rule 1; three other bench100 pages are the same): resolve answers `incomplete` after 135,979,278 bytes (119,948,577 before the cap rose: it now does more work before it is refused) and `reference` to it is `NoIdentity`, so it can't be referenced with certainty.
- **The work limit is exact for a build, not for a byte.** Each stage of a stream's chain is charged for what it reads from the one before, and a stage reads ahead (inflate's input buffer and the base-85 and run-length `BufReader`s take up to 64 KiB each), so a page near the 256 MiB limit gets or lacks an identity by up to 64 KiB per stage of decoded bytes past the hashed prefix, and by how flate2 reads. The same build gives the same answer and no digest changes, but a flate2 upgrade could move pages that sit right at the limit.
- `resolve`'s `page` is as the tab shows it, which may be the old bytes before the app has looked, the same as `text`.

## `--ref` on `text` and `render`

`recto text --ref <ref>` and `recto render --ref <ref> --out <file>` read the page a reference points at now, in place of a page number. They resolve through the same resolver as `resolve` (`crates/recto-agent/src/locating.rs`, `page_of`, `ScanCaps::STANDARD`) and then read through the same `locate` path as a page number, so the levels (`text` Read-only, `render` Full), `DRAWS`, `READS_PAGES`, the protected-document refusal and `render`'s file rules are the commands' own and are not repeated for `--ref`.

**Page or `--ref`, not both.** The line carries `page` or `ref`; both or neither is `usage` (exit 2) in the command's own words. A token that can't be a reference is refused as the line is read (`bad_reference`, or `reference_too_new`), before the level or the tab is asked, and its words never repeat it. A reference's spot or characters don't narrow `text` or `render`: they read the whole page, but a reference to characters is read only while its characters are checked and the same (below).

**Only a page gives a read.** `found` and `moved` give a page. `gone`, `ambiguous`, `incomplete`, and a page that unsaved edits removed from the tab are each refused with their own constant words as `reference_unresolved` (exit 3, not found), and nothing is drawn or told to the host as drawn. `text_changed` is the one refusal that is not before the draw: on `text` it is known only after the read, because `text` checks a reference's characters against the very text it read (`CharsChecked::AgainstItsText`: `page_of` reads no text, and `attach` checks with `held_characters`), so the page, found by its content digest, is drawn and told, and then the read is refused with no text in the refusal. `render` keeps its check before the draw (`CharsChecked::First`), where `text_changed` draws nothing (this is about the unresolved case only: once a page is read, the draw happened and is told, and a refusal after it, for a changed file, doesn't undo that). The next step says `recto resolve` shows where the reference points and lists any candidates. A `document: different` answer still reads; the answer says so.

**The answer** carries `ref: { status, was_page, file_page, document }` (no token), and for a reference to characters also `text: "same"` and `chars: [start, end]`, with `untrusted.hit` the characters themselves, cut from this answer's own `untrusted.text` (an answer with no text is refused, so unchecked characters never pass). `page` is the page's place in the tab as it was found. The tab is settled once, where the reference is found (`--tab` is resolved there, and the active tab moving later changes nothing, as for a page number). Before the read, the page the tab gives for that place must be the page that was found (`agree`): if a page added from another PDF or another page of the file stands there, the refusal is `file_changed`, "The tab changed while the reference was being found. Try again." (the only place those words are used). The file's stamp is checked after the read (`still_located`): if the file changed since the page was found, the refusal is `file_changed`, "The file changed while it was being read. Try again." For `render`, the picture this command wrote is taken away when that refusal is made (exactly `--out`, which it created), so a retry isn't `output_exists`. The session lock is held only where `resolve` holds it (inside `tab_file` and the page lookup), never during the scan. The activity log holds `ref_page` (the page the token hints at), never the token.

## `--ref` on `goto`, `select`, `copy`, `highlight`, `snapshot`, `export svg`, `images` and `image`

The flag is `--ref` (not `--at`, which already means a point on `select`, `copy`, `highlight`, `image` and `images`, and a position on `page insert`), with the same token, `bad_reference` words and `page_of` as `text` and `render`. Only `found` and `moved` give a page; every other case is `reference_unresolved` in the words `text --ref` has for it, and then nothing happens: no jump, edit, file or draw notice. The tab is settled once, in `page_of`, and the command goes on in `found.tab_ref()`. Each command keeps its own level, the protected-document refusal (before anything is resolved, for any valid token), and the one edit path; an agent below Full gains nothing.

**What each does with a reference, and what is refused as the line is read** (`commands/locating.rs` holds the words, each command's `line` the reading):
- `goto --ref` goes to the page found as the tab has it among its edits, with `--within`. A page, a label, `--entry` or `--link` beside it is `usage` (`GOTO_REF_ALONE`). A reference to characters is checked first (`CharsChecked::First`), so one rule holds for every `--ref`. The answer is `where`'s, with `ref`.
- `select --ref` and `copy --ref` pick exactly `--page P --chars S-E` for the page `P` found and the characters the reference names; a reference to a page or a spot picks the whole page. The page found is read once, by the pick's own read (`selecting::Pages::read_checked`): the page must be the one found (`agree`), and the characters are checked against `recto_index::read_page`'s text of the same characters, which is what `text` gives (`Located::held_in`), so no second read is made and no worker is started for it. A page that can't be read at all, for a reference to characters, is that read's own refusal, as `text --ref` has it. Another pick (`--page`, `--chars`, `--at`, `--to`, `--unit`, `--to-page`, `--all`) beside the reference is `usage` (`PICK_REF_ALONE`); `--anyway` goes with it.
- `highlight --ref` takes only a reference to characters and highlights exactly those. A reference to a page or a spot is `usage` (`HIGHLIGHT_REF_CHARS`): a page reference from an `also_spelled` hit would otherwise mark a whole page, an edit nobody asked for, and `--page` stays the way to do that. The file is checked to be the version the page was found in (`still_located`) just before the edit, and the answer carries `ref`.
- `snapshot --ref` and `export svg --ref` take the page only; `--rect` still applies and a spot never narrows. A reference to characters is checked first, as `render` does. `snapshot` refuses `--ref` with `to_clipboard` or `as_seen` when the line is read (`SNAPSHOT_REF_NOT_CLIPBOARD`): the clipboard is the person's, of the page they saw. A file written is taken away when the answer is refused (`attach_new_file`).
- `images --ref` lists every image of the page found, as `images --page P` does, and the answer adds `ref`. A spot never narrows it, and `--at` (and the wire-only `as_seen`) beside it is `usage` (`IMAGES_REF_NO_AT`): a point belongs to the page as it was seen, and a page found by its content may have a new crop or turn; `resolve` followed by `images --page P --at` is the explicit route. `image --ref --number N --out F` takes image N of the page found. The page digest (`recto-page/1`, `page_id.rs`, part 3) covers every image the content draws, by name and bytes, in order of first use, so a page found by its digest numbers its images as `images --ref` listed them. `image --ref` with `to_clipboard`, `at` or `as_seen` is `usage` (`IMAGE_REF_NOT_CLIPBOARD`), refused as the line is read; and an `Image` built in Rust with a reference and the clipboard is refused in `run` first, for any actor, before the window's sink is asked. A character reference is checked first (`CharsChecked::First`) and gives the page; `image` checks that its file is new before resolving, writes only for a page that was found and agrees, and takes the file away when the answer is refused (`attach_new_file`).

**A `--ref` line draws.** `goto` is not a command that draws, waits or reads pages when it goes by number or label, and is one that does all three with a reference, because finding the page scans the file: it must take a place under the server's draw cap and never run on the window's session thread. So `Cmd` has `draws_as_asked`, `waits_as_asked` and `reads_pages_as_asked`, which default to the constants, and `Goto` overrides them. The other seven already say true.

**Wire.** `ref` is last on every line and left out of what is sent when there is none, so every existing line, positional array and golden reads as before. `export svg` and `snapshot` with neither a page nor a reference (before: not a command) are `usage` now, as `text` and `render` are.
