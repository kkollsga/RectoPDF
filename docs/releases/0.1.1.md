RectoPDF 0.1.1 fixes security faults found in 0.1.0, fixes what 0.1.0 got wrong for people reading in it, and adds highlights. Every fault 0.1.0 is known to have is named below, the security ones first.

## Install

macOS 15 or later, Apple silicon. Download [RectoPDF-0.1.1.zip](https://github.com/kkollsga/RectoPDF/releases/download/v0.1.1/RectoPDF-0.1.1.zip), open it and drag RectoPDF to Applications. It's signed with a Developer ID and notarized by Apple.

**Updating from 0.1.0.** RectoPDF 0.1.0 finds this release within a day, and the RectoPDF menu offers *Update to 0.1.1…*. With *Update automatically* on, it installs once you haven't touched the app for 30 minutes, and the app comes back as you left it. Each tab that was asleep wakes once from its PDF, as 0.1.1 keeps no picture of any page and removes the ones 0.1.0 kept (see the first security fix).

## Security fixes

Each of these was in 0.1.0. None of them sent anything off your Mac. All of them concern programs you run yourself, such as a script or an AI agent using `recto`, being able to see or do more than the access level you gave them.

- **Pictures of your pages were kept where any program you run could read them.** So that an idle tab came back at once, 0.1.0 kept a small picture of the pages where you were in it, in the app's own folder, for up to 30 days, pages of a PDF in a folder macOS protects (such as Desktop or Documents) included. Now no picture of any page is kept. An idle tab comes back at its place with its pages on their paper, the right size and colour, and each fills in as it's drawn, in about a tenth of a second for a page of text. The pictures 0.1.0 kept are removed the first time 0.1.1 starts.

- **The text kept for Find could be read by any program you run.** So that a search is fast, 0.1.0 kept the text of each PDF you searched as plain files in the app's cache folder, for up to 90 days, including the text of a PDF in a folder macOS protects (such as Desktop or Documents). Now it's stored encrypted, each PDF's under its own key, from a key RectoPDF keeps in your keychain where only the signed RectoPDF release can read it. The text 0.1.0 kept is removed the first time 0.1.1 starts, so the first search of each PDF after updating builds its Find text again.

- **A program could give itself full access to your PDFs.** Any program that could run `recto` on your Mac could start a separate test session of RectoPDF on a folder of its own. That session gave it Full access, whatever level you had set (Off included), so it could open, read and change PDFs anywhere you can. Now a test session can't reach any file outside the system's temporary folders, by any route.
- **Agents learned things about password-protected documents from the app's events.** An agent watching the app, at Read-only or above, was told which pages of a password-protected document were being drawn as you read it, and the hits of your own Find in it. At Control it could also read what you had typed into Find. Now nothing of a password-protected document reaches a watching agent except that its tab opened, came to the front, closed or is in a comparison.
- **The same, through a side-by-side comparison.** With a password-protected document compared beside another PDF and scrolling synced, an agent could read the protected document's length, and where you were in it, from the other PDF. Now where the other PDF was left by following the protected one is withheld from agents until you next go to a page in that tab yourself.
- **A password was used beyond the tab you typed it for.** With a specially made PDF, a password you typed for it was also used for its pages added to another document. Those pages were then drawn there, visible to agents, found by Find and kept in that document's saved picture. And after you closed the protected tab, opening the file again could show it without asking for the password. Now a password serves only the tab it was typed for and ends when that tab closes; pages like these say they aren't shown; and no picture of any page is kept.
- **An agent's command-palette run could act as you.** An agent at Full running a ⌘K row that has no command of its own ran it as if you had chosen it in the window, past the rule that keeps agents out of password-protected documents: it could turn a page of such a document in edit mode, or open Find in it with your password. Now an agent's palette run is always the agent's own, and a row that is only yours is refused.
- **An agent could throw away your unsaved edits.** An agent at Control could discard your unsaved edits, or clear their undo history, in a tab that had gone to sleep and whose saved history couldn't be read back. Now that is refused at every level.
- **An agent could read your print.** While the system printed a PDF that asks not to be copied, the file prepared for the print was in the temporary folder under a name an agent at Control could work out, so it could open it and read the pages without the "anyway" step and without the log saying so. Now that file has no name an agent can find, and is readable only by you.

## Fixes

- **The one backup RectoPDF keeps of a PDF before its first save** was dated with the original's last-change time, so for a file last changed over 30 days ago the backup was removed at the next launch; its 30 days now count from when it was made. A backup that 0.1.0 already removed can't be recovered.
- **The undo history kept for a closed PDF** is now kept 30 days from when it was closed. A history that a crash had left behind for a PDF last edited over 30 days earlier could be removed at the next launch.
- **The activity log** kept the words of a command-palette search an agent sent; it now keeps only that one was given.
- **The copy of your session kept for a week after an update**, which includes your edit history, is kept out of Time Machine from the first time 0.1.1 starts, as the history is. That includes the copy made by this update.
- **Find's result rows** in the sidebar: text in a PDF that reorders or hides characters (right-to-left overrides and similar invisible marks) could change how a row was drawn; such characters are now left out of the rows. Rows now start and end on a word.
- **Clearing the Find text, and going on from an index build that was interrupted,** no longer wait for ever when something other than a plain file sits where a document's index files go, and no longer follow a link there. In 0.1.0 a program of yours could leave such a thing in the cache folder, after which clearing the Find text never returned, an interrupted index build and the ones queued behind it never went on, and a link there could have a file elsewhere cut short.
- **Print** and the **Snapshot tool** work on a PDF you opened with its password. In 0.1.0 both said "This PDF needs a password." Save as PDF from the print panel makes an unencrypted copy, as you asked for it.
- **Quitting** waits a moment, at most 5 seconds, for an edit, a save or an agent's command that is under way, so it isn't lost. 0.1.0 wrote your session at once and could lose it.
- **Find** (⌘F): its field now has the keyboard as soon as Find shows. In 0.1.0 it came one moment later, so a key typed straight away could go to the page.
- **A late restore** no longer puts the saved selection and the contents' scroll back over what you had chosen since.
- **Idle tabs** (what a tab keeps while it's idle, so it comes back at its place):
  - a PDF anyone may open but which is encrypted (many government and UN reports) kept nothing and always woke from its PDF;
  - a tab could stop keeping it for good;
  - a tab closed, saved or changed while that waited to be written left it on disk, with the contents' titles, until the 30-day clean-up.
- **Drawing:** pages stopped drawing for good if macOS once refused the memory for a page; now it tries again. A comparison pane closed while drawing kept its memory until you quit.
- **Settings:** choosing a setting in the first moments after launch could reset the update settings: *Update automatically* back on, and what the app had learned about failed updates forgotten. If you turned *Update automatically* off in 0.1.0, check it's still off.
- **The window:** with the sidebar hidden, the window buttons now come back when you point at the top left corner, and pages are centred between equal margins at any width.
- **Unsaved edits on a file another program changed** are kept, aren't read or saved as if they fitted the new version, and the notice says which case it is. In 0.1.0 the refusal and the Save sheet offered Save As to keep both versions, which was then refused too, so the edits could only be thrown away. See also *Known limits*.
- **While unsaved edits are held** because another program changed their file into a version they don't fit, none of the file's pages is shown, the tab says so, and Discard shows the file as it is. In 0.1.0 the tab could keep showing pages of the earlier version, and showed the new file's pages under the edited document's page numbers, with blank pages past its end and its text selectable.
- **Rarely, an edit could be lost** if RectoPDF was force-quit within two seconds of making it, about once in the life of a session folder.
- **Comparisons** leave nothing behind in memory after they end.
- **A notice goes once you've left its tab by opening another PDF,** as it does when you go to another tab. In 0.1.0 a file's "moved" or "changed" notice on a tab with no edits, or the notice that undo can't go back as far, stayed on the tab you left that way and was shown again when you came back.

## New

- **Highlights.** Select text, then **Mark Up › Highlight** (⌃⌘H). **Remove Highlight** takes one off, a highlight already in the file included. Highlights are steps of the same undo history as your other edits, and Save adds them to the end of the file as standard PDF highlights, which other PDF apps show.
- **Your edits happen in the order you asked for them.** ⌃⌘H then a quick ⌘Z undoes the highlight, and Undo and Save can be chosen while an edit is still landing.
- **The contents follow you more closely.** The current entry is the one at or above the top of what you're reading, not the last one on the page; it moves as you scroll within a page; a click goes to the entry's own place on its page; and folding a section that holds the current entry marks the section.
- **Dark paper** now goes by a page's background: a page that is mostly photographs on white turns dark with the photographs keeping their colours, and a page that is already dark is left as it is.
- **Unsaved edits follow their pages** when another program changes the file: each goes onto the same page of the new version, wherever that page is now, and pages the other program added are there. If any page an edit uses can't be found for sure, nothing is moved and the edits are held, as before.
- **Settings shows an update that's waiting,** with an *Update now* button.
- **Find says why** when it can't search a file.
- **A window opened while the RectoPDF before it is still closing** keeps trying for about ten seconds to get your session, and brings it back when it does. 0.1.0 gave up after 0.6 seconds and started without it, and nothing you did in that window was remembered.

## For scripts and agents (`recto`)

- **New commands:** `recto highlight` (Control), `recto highlight remove` and `recto highlights`; `recto contents fold`, `contents show own|generated` and `contents stop`; `recto edit mode on|off`. Each is the same command the window sends.
- **New options:** `goto --entry N` and `--within`; `find --jump`, `--hit N` and `--open`; `compare --toggle <tab>` and `--reading <tab>`; `view --sidebar toggle`, `--agent-icon toggle`, and `--tab` with `--layout`. `recto contents` and `recto sidebar` give each entry's place, where a click on the row goes.
- **A withheld place.** A plain tab that was following a password-protected one in a synced comparison has its place withheld from agents. Its answers say `place_withheld` and give no page, and commands that start from its place are refused with `place_withheld` (exit 8). Its length and words are still given. Nothing an agent sends lets the place go, its own `goto` included: only the person's own jump does (typing a page number or label, or clicking a contents row). A link followed or a Find hit chosen from the list keeps it withheld, whoever does it, and the flag is kept across a restart and an update.
- **Edits that followed a change:** watchers hear `edits_followed` (in the `edits` group, with the tab, its length and how many edits followed), and `edits` gives `followed`: how many edits, and the version's size and modification time. Counts only.
- **Password-protected documents:** watchers hear only `tab_opened`, `tab_activated`, `tab_closed` and a comparison's `view_changed` for such a tab. `tabs`, `where`, `session show` and `sidebar` give it no `edited`, undo or redo, and `session show` no zoom, layout, notice or Find query.
- **Changed answers:**
  - `save` refused because the file changed on disk is now `changed_since_opened` (it was `file_changed`); a file that couldn't be read is `file_unreadable`; a Save As whose file changed while it was copied is `changed_while_copying`.
  - A request whose arguments don't fit together is refused as it's read, with `usage`, before the level, the tab or the app are looked at; a refused command keeps its own name in the reply and the log.
  - Events come only when something changed: `tab_activated` only when a tab came to the front, and `edits_changed` from Clear History only when there was history.
  - `discard` and `clear-history` on a tab whose edits can't be read back are refused at every level, with `edits_unreadable`.
  - `palette --run` runs a row's own command at that command's level; a row that is only the person's is refused with `persons_own`, and one with nothing to do now with `nothing_to_do`.
  - Only the person's own snapshot goes to the clipboard. An agent asking for the clipboard is refused, and is told to give `--out` or `--as text`.
  - `print` still needs `--to-pdf`. A print with no file is only ever the person's, at the window.
- **New refusal codes:** `place_withheld`, `persons_own`, `nothing_to_do`, `no_such_entry`, `not_a_section`, `no_such_hit`, `not_side_by_side`, `no_such_highlight`, `too_many_highlights`, `highlight_in_added_file`, `no_text_there`, `changed_since_opened`, `changed_while_copying`, `edits_dont_fit`, `edits_version_unknown`, `outside_quiet_run`, `qa_refused`, `not_the_shown_tab`, and for `update install <zip>`: `not_handed_over`, `no_handover_folder`, `not_rectopdf` and the `zip_*` codes.
- **Test sessions** (`recto qa start`) reach no file outside the system's temporary folders, and the test commands that act as the person don't exist in a release.

## Known limits

- **Unsaved edits when another program changes the file:** when you come back to the tab, your edits follow their pages onto the new version if every page they use is found there, and the tab says so; Undo can't go back past that change. Otherwise they are all held, as before, until the earlier version comes back. Setting single edits aside, so the rest can follow, comes in a later release. The edits of a document you opened with its password are always held.
- A file put back from a backup with the same bytes, under unsaved edits, is now told as changed by another program, and the undo history ends there, where 0.1.0 took it back silently.
- On a disk whose files change their number when rewritten (some network and cloud-synced folders), each time a sync puts the same file back under unsaved edits, the edits follow it, the tab says so, and the undo history ends there.
- After unsaved edits followed another program's change, Save writes them over that program's version. RectoPDF keeps one backup of a file before it first saves over it, so if one was kept earlier, the other program's version isn't backed up again.
- If a copy goes back to 0.1.0 (by itself after an update that didn't come up, or by hand) and later forward again, a tab with highlights can wrongly say some of its edits couldn't be read back, and an edit made to that tab in 0.1.0 meanwhile hides its highlights from view; they stay on disk.
- A change made to an open file by another program is noticed when you come back to RectoPDF, not the moment it happens.
- **Printing** sends pictures of the pages, not text. On a Mac that is very busy, a print or an export can stop with "This file took too long to open." and isn't tried again: try again.
- Find highlights only the hit you're on, not every hit on the pages shown.
- Copying text still sometimes keeps a running header or page number, or leaves out a short line it takes for one (a table's header row, a caption, a map legend's label).
- On dark paper, a few images are still turned dark when they shouldn't be (a map of a few flat colours, a small shaded photo on white) or show a grey box.
- The sidebar's lists can't yet be reached with the keyboard alone.
- A very large PDF (10,000 pages) takes about a second to open the first time, as its whole page list is read first.
- Switching to an idle tab, or opening a file, shows its pages as plain paper for a moment (about 0.1 s) before they're drawn. The first time each idle tab wakes after the update, it reads its PDF first, and its pages appear as they're measured. A document you opened with its password always does this, and so does a document with a very large table of contents (over 256 KiB).
- Pasting a snapshot as SVG can wait up to 3 seconds for a very large page.
- If you quit and reopen at once on a very busy Mac, the new window can be without your session for up to ten seconds, then gets it back.
- Passwords you type aren't wiped from memory when you're done with them, and there's no way yet to let an agent read a password-protected document.
- Without the app running, `recto` has no key for the Find text, so a search from the command line reads the PDF's pages one by one and says `route: scan`, and `recto index` there is refused (`no_find_key`). That is about 10 to 60 times slower than the app's index on the files measured (NASA's 383 pages: 1.2 s against 36 ms). With the app running, `recto` asks the app and gets its index.
- The encrypted Find text can't be read by another program, but one that runs as you can still see that it's there and how big it is, and delete it, which only costs a search to build it again. A copy of RectoPDF that isn't the signed release (one built by hand) keeps its key in memory, so its Find text doesn't last past the run. `recto index --agent` also writes a plain copy of a PDF's text, as Markdown files that any program you run can read, until RectoPDF quits and next runs.
- When you print a PDF you opened with its password, its unencrypted print file has a name for an instant before it's removed, and a program you run could open it in that instant. Nothing an agent sends through `recto` can.
- **For agents:** while a tab's place is withheld, the person's own highlight or edit on its page names that page, and the app's counts of what it has written still change as the person moves (how much, not where). An agent at Off sending commands non-stop fills the activity log in about two and a half hours, pushing out older lines.
