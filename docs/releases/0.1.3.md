# RectoPDF 0.1.3

RectoPDF 0.1.3 improves copied table text, prepares snapshot SVG before paste, and moves more print preparation off the window’s thread.

## Fixes

- Certain repeated table-column labels were mistaken for running headers and left out when copying across pages. Those labels now remain in the copied text.
- Snapshot copies prepare SVG alongside the other clipboard formats. Pasting no longer starts that SVG rendering work. Complex snapshot copies may take longer to finish because this work happens during Copy.
- Paper-size and margin reads, and opening the prepared print document, now run in the background. Pending print preparation stays with its original window and operation, including when a window closes or another job starts.
- Saving over a downloaded PDF preserves its original download-origin metadata when carrying the file’s access permissions.
- Update recovery now confirms the failed app has exited before restoring its saved state and previous version. If exit cannot be confirmed, recovery stops and preserves the recovery files.

## Known limits

The remaining limits documented for [0.1.2](https://github.com/kkollsga/RectoPDF/releases/tag/v0.1.2) still apply.

- Startup and window layout can still exceed the 16 ms target. An unexplained 2.804-second startup stall recorded during testing remains open.
- The reported missing horizontal scrollbar on pages wider than the window remains unreproduced.
- A 1,000-tab input-latency benchmark had one unexplained tail increase; a control using identical binaries passed. The original result remains under investigation.
- Header/footer filtering remains heuristic and can misclassify other repeated text. This release fixes the identified table-column case.
- An update that leaves its new app running or whose launch is uncertain cannot automatically roll back. The updater preserves the recovery files rather than restoring over a possible live writer. Updates started by older installed versions still use that older version’s updater.
