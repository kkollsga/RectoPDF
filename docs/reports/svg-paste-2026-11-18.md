# Prepared snapshot SVG — 2026-11-18

The existing asynchronous snapshot command now prepares SVG before publishing the clipboard offer. The synchronous `clipboard_data` bridge takes matching prepared bytes once; it submits no command and waits for no rendering or session lock. PNG/text/SVG/JPG retain their order. PNG and JPG still share one drawing. SVG uses that job's existing worker, stop word and output caps: 32 MiB per type, 64 MiB total, including the already-made JPEG. Oversized SVG is omitted with a notice; other SVG failures leave the usable types and explain that SVG could not be copied. Copy restrictions, actor policy and password handling are unchanged.

Legacy explicit-promise actions remain for compatibility and cancellation tests; the host no longer invokes them and new snapshot offers contain no promised type. This change does not claim to remove every historical promise method or the separate print wait.

## Before and after

One pair per case, release builds on this 16 GB Mac. `HEAVY_SOLO=1` held the local heavy queue with no other queued build running during each measurement. The existing `recto-agent/examples/clip_memory.rs` samples whole-process `phys_footprint` every 5 ms for its CLI host and workers. These are not native app/NSPasteboard retention measurements, statistical estimates, or a claimed memory optimization. Baseline implementation is `ae0bf8a2` (the checked main had only documentation changes); after is the prepared-SVG source on this branch.

Public corpus: `distillPDF/benchmarking/bench100/rfc9110.pdf` page 1, box 40,40,500,700; `gov_usgs_usgs70277338.pdf` page 1, box 0,0,1000,1000. Times are seconds, footprints MiB; tree means the simultaneous sampled host-plus-workers peak.

The helper drops its first clipboard before measuring the separate baseline SVG request, so those peaks must not be added or presented as retained native clipboard memory. Worker peak and sampled tree peak are measured by different mechanisms and need not line up exactly. Preparing SVG costs time even for a paste that later uses only PNG. That is the explicit cost of removing rendering from the synchronous callback; cancellation and the one-job rule remain necessary.

Evidence: `/tmp/rectopdf-20261117-start/svg-{baseline,ready}-{text,map}-memory.txt` on the development machine. The repository records the numbers so the temporary evidence is not their only record.

## Input to frame

The existing release headless input-to-frame measurement ran once before and once after, under the solo queue, for 54 action/tab-count rows (1, 100 and 1,000 tabs). UI-call p99 ranges were 0.2–3.3 µs before and 0.2–3.0 µs after; published-frame median ranges were 26.2–344.2 µs and 25.0–336.8 µs. Both runs passed (4.835 s and 4.699 s). These cover the headless publication path, not native display timing or a statistical speedup; there is no claim that the separate ~40 ms native stall is solved. Full row evidence: `svg-baseline-input-frame.txt` and `svg-ready-input-frame.txt` in the same temporary evidence folder.

## Regression evidence

- A copied box's advertised SVG must already contain bytes, and all advertised types share the existing byte cap. Seeding the former late-SVG implementation made this test fail.
- A copy's SVG and PNG remain the copied page's after that page moves. The former late-SVG seed failed the rewritten regression; final source passed.
- A prepared SVG is returned while the session is deliberately held, with no paste command or new copy job. The holder waits for the sole release sender to be dropped, never an elapsed-time release. Review caught the former holder timeout that could mask a lock-taking callback. Injecting session acquisition in that callback failed at the bounded receive, then released the holder and joined both threads safely (20.195 s); final source removes that seed.
- Those three focused tests passed 20/20 CI-like rounds. Existing legacy promise timeout/cancellation guards explicitly offer a legacy promise rather than relying on normal copies to create one.
- The existing CLI clipboard test now validates prepared SVG along with type ordering; its former late-SVG seed failed. The held-session test also failed on that seed. Hidden-text and rotation guards remain.
- The broader quick run exposed stale legacy-action setup in the control inventory and protected-document walks, plus an unnamed test thread. Their setups now mirror the prepared host path or explicitly inject a legacy promise, and the callback thread is named. The two existing macOS failures (quarantine and `tmutil`) are addressed in separate commits, not hidden by retries. The owned stuck `tmutil` was terminated after the cause was already established; that quick run failed and is not counted as a pass.
- Release clippy also exposed an unrelated debug-only `Duration` import; commit `d0e2d798` gates that import. Release lint failed before and passed afterward.

The merged result still needs its one full gate. No real paste into another application, native retained clipboard footprint, or new drawing was measured by this helper. The changed path has no new visual control; native app assurance remains in the existing quiet-app suite.
