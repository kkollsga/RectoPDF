## Installer cleanup findings

A stranded helper from an earlier test was traced to `updater::builds::tests::going_back_lands_on_a_build_only_with_the_switch_on`: its rollback path bypassed the fake host and detached a copied `/usr/bin/true`, after which the fixture was removed. Its loader stall is unexplained; the sample does not show a Rust installer wait. The reviewed correction routes Install and Back through one real launch implementation and the injected host seam. The existing rollback test removes the fixture helper and proves Back is captured exactly when allowed, so even its failed-first run cannot strand a helper. Both named seam tests passed.

The subsequent source review found separate older defects. `tests/installer.rs` teardown signalled PIDs discovered by executable path; its reviewed replacement uses a private cooperative fixture stop marker and bounded exit observations. Actual direct children have a bounded retirement guard: ownership errors send no signal, reaping is nonblocking, and one capped failure record is latched into fixture retention even if a later executable scan reports absence. The existing marker guard failed first against the old stand-in; an injected ownership error failed first against the initial guard. Three final targeted tests passed in 0.194s on one local run, and targeted Clippy and ratchet checks passed. No new real-app launch case was added.

In production, the reviewed old `install.rs::stop_new_app` signals discovered PIDs, and `go_back` restores the record and swaps bundles even after both stop waits expire. Restoring files while the new app may still write them is unsafe. On resumption the owner said "What do you mean rollback safety? Lets publish". The coordinator proceeds with a small fail-closed guard: only actual retained direct-child handles can be cancelled, an unowned GUI launch must have been observed before absence proves its exit, failed/unknown observations refuse restoration, and the normal session writer lock protects the mutation. A larger stable OS launch controller is deferred. The notes state that unprovable/hung GUI recovery stops and keeps its files, and that older installed copies still use their older updater. The final full check, main CI, signing preflight and signed draft gates wait for final corrected source; none is claimed here yet.

The first ad hoc `.app` copy and the repository's temporary built `.app` were retired after these checker proofs: scoped process observations found no live/unknown processes, and exact main/helper registration absence was proved before removal. Zipped evidence remains. The managed tools worktree is protected as the chat's primary checkout, so the archive API refused its removal; this is tooling protection, not an extra installed application. The old detached `/usr/bin/true` test helper has no retained child handle and was not signalled by a discovered PID; its earlier source leak is corrected, but that already stranded process is not claimed reaped.
