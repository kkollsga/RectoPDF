# What may differ between a session as 0.1.0 left it and as 0.1.1 shows it, by design, each with its reason: a path of `qa state` (or `tabs.`, `show.`,
# `permission.` and so on for those answers), then why. Beside these, the restore tests' own exceptions hold (crates/recto-cli/tests/restore/exceptions/).
# A key names a path and everything under it; `[*]` in it stands for any index of a list. A key that starts with an answer's name (`edits.`) is every
# tab's answer of that name (`edits #1`, `edits #2`, ...). The check holds each by-design difference to what its line says, not only leaves it unread.
# `fault:<where>` names a fault found and reported, which the check says as KNOWN FAULT instead of failing on.
app.menu_bar The menu bar is the build's, not the session's: 0.1.1 adds Mark Up (Highlight, Remove Highlight) before Tools, and each item says its key mask and whether it is the system's.
app.save_button.frame Not the code: no source that places the window's buttons changed between these releases. A build made on this Mac links macOS SDK 15.0 and the release workflow's link 26.5 (`vtool -show-build` on the app's main executable), and the buttons sit at y 8 in the one and 7 in the other (the published 0.1.0 and 0.1.1 are both 7): AppKit lays the titlebar out by the SDK an app links, which is inferred, not built here to prove. So a local dress rehearsal differs here and the draft, built by the workflow, shouldn't. (Until 2026-11-16 this line said 0.1.1 moved them a point lower, which it didn't.)
app.sidebar_button.frame As app.save_button.frame.
permission.set_at_ms A quiet run sets its level as it starts, so the time it was set is that run's.
edits.followed New in 0.1.1 with the page matcher (merge 888b6d0e, build/page-matcher-2): `edits` says which unsaved edits followed their pages onto a file changed on disk. No file changed here, and the check holds that each tab says nothing followed (null).
app.find.rows_on_screen[*].untrusted.label 0.1.1's Find rows start and end on a word (merge 3ae12808, build/on-screen-fixes): a row 0.1.0 began inside a word ("…cond line") begins at the next one ("…line"). The check holds that each changed row is 0.1.0's words cut at a space.
reader.left_picture_bytes Gone with the pictures of pages, by the owner's decision of 2026-11-15 (merge a1b29d9d, build/no-page-pictures): no picture of a page is kept, so there are no bytes of one to say.
fault:D.notice.edits_unreadable Found 2026-11-15 by this check, reported: after 0.1.0 has run on 0.1.1's state (a copy that went back), its record carries `notice: edits_unreadable` for the tab whose journal it left alone, and 0.1.1 restores that notice next time though it reads the journal whole. The edits are all there; the words are wrong.
fault:F.highlight_hidden Found 2026-11-15 by this check, reported: after a copy went back to 0.1.0 and an edit was made there on the highlighted tab, 0.1.0 starts a journal of its own (version 1) beside 0.1.1's version 2, and 0.1.1 next time keeps 0.1.0's list: the highlight isn't shown, and nothing in the app brings it back. Since the crash rule of build/page-matcher-2 (merge 888b6d0e, review M2) 0.1.1 sets the version-2 journal aside in the state folder as `journals/journal-….not-merged`, the store's name for a list it keeps and won't read (nothing prunes it, and 0.1.0 leaves it alone); before, it stayed under its own name. The check holds that it is there byte for byte.
fault:F.notice.edits_set_aside_after_quit Found with F.highlight_hidden, first as `edits_not_merged` ("open in two tabs", which it wasn't); since build/page-matcher-2 (merge 888b6d0e) the tab says `edits_set_aside_after_quit`. What it says of the lists is so (one shown; the other, the highlight's, kept in the state folder, which the check holds), but it begins "After an unexpected quit", and there was none: a copy went back to 0.1.0 and an edit was made there.
